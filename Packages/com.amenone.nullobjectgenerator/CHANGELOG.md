# Changelog

## [2.0.0] - 2026-11-27

`NullObjectGeneratorForNewerThan2022.2`（VContainerExtensions に同梱していた DLL）を、このパッケージとして分けて作り直した。

### Changed
- Unity 6（6000.0）以降が対象。`Microsoft.CodeAnalysis.CSharp` 4.3 でビルドし、Roslyn 標準の `ForAttributeWithMetadataName` を使う。
- DLL を asmdef の下に置かず、プロジェクトの全アセンブリで動くようにした。属性と `NullObjLog` は、アセンブリごとに internal で生成する。
- 型ごとに等価比較できるモデルを作り、型ごとに出力する。1 つの型を編集しても、他の型の出力は再実行されない。
- 生成コードの型を全部 `global::` 付きで書くようにした。元の版がしていた、interface のファイルの `using` を写す処理は無くした。
- 生成ファイルに `// <auto-generated/>` と `#nullable disable` を入れた。
- `Task` は `Task.CompletedTask`、`Task<T>` は `Task.FromResult<T>(default)` を返すようにした（元は `default`、つまり `null`）。プロパティの getter も同じ。
- 同じシグネチャのメンバーが複数の interface にある時、2 つ目からを明示的な実装にした。
- `public` の生成型で、シグネチャに `public` でない型を含むメンバー、型引数の置き換えで制約が書けなくなるメソッド、`object` のメンバーと同じ形のメンバーを、明示的な実装にした。
- `[InheritsToNullObj]` で、生成される型から見えない interface（private の入れ子、別アセンブリの internal）を実装の対象から外した。
- 生成される型にコンストラクターを書かないようにした（元は型と同じアクセス修飾子のコンストラクターを書いていた）。

### Fixed
- 属性の引数の `NullObjLog` が無視されていた。各値が効くようにした。
- hintName が型の名前だけで、名前空間が違う同名の型があると生成が止まっていた。名前空間・入れ子・ジェネリックの数を含めた名前にした。
- イベント、インデクサー、`init`、ジェネリックなメソッドの制約、複数の `out`、ジェネリックな interface、入れ子の型、既定値つき引数、`UniTask<T>` を返すメソッドで、コンパイルできないコードを出していた。
- `ThrowException` の時に `throw` の後へ `return default;` を書き、到達できないコードの警告（CS0162）が出ていた。
- 対応できない形で、壊れたコードの代わりに診断を出し、その型の生成をやめるようにした: `ref` 戻り値（`NOG001`）、static abstract（`NOG002`）、private / protected の入れ子の型（`NOG003`）、生成される型の名前の重なり（`NOG004`）、入れ子のジェネリックな型での型引数の名前の重なり（`NOG005`）。
